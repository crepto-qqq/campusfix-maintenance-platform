# 维修人员评分、评价与审核

## 评价资格与内容

- 工单进入 `COMPLETED` 后，提交该工单的学生才可评价最终完成工单的维修人员。曾经接手但被改派的人员不计分；即使一个账号兼有学生和维修角色，也不能评价自己完成的工单。
- 每张工单最多一条当前有效评价。学生在 `GENERAL_USER` 模式下给出 1–5 星整数分；文字可选，为不超过 1000 字的纯文本。首次提交不限期限，以后可随时修改同一条评价。
- 后端按工单提交人、状态、最终完成人、活动角色和账号封禁状态验证每次写入；页面隐藏按钮不能替代接口授权。
- 已完成工单的提交人可在工单详情打开自己的评价。学生还有独立的维修人员评价列表，可浏览全部公开分数与合规文字。公开页面只显示维修人员、星级、文字和日期，不显示评价作者、工单编号、标题或位置。

## 角色可见性

| 当前活动角色 | 可查看 | 可执行 |
|---|---|---|
| `GENERAL_USER` | 全部公开评价及汇总；本人对工单的评价 | 给本人的已完成工单评分、修改评价、举报公开评论；封禁期间只保留阅读权 |
| `MAINTENANCE_STAFF` | 仅本人的真实平均分；无逐条评分、评论、作者或排名 | 无评价操作 |
| `ADMINISTRATOR` | 完整评价、作者、关联工单、举报及审核记录 | 审核、恢复、处理举报、封禁和解封；不能审核自己的评价、处理自己的举报或解除自己的封禁 |

兼有多种角色的账号切换到学生或管理员模式后，按该模式查看信息。这是管理员授权多角色时需要考虑的可见性边界。

## 派单辅助排序

`GET /api/tickets/technicians` 仍仅向管理员开放。列表只含启用且拥有维修权限的账号，先列**当前无未完成派工**的人，再列有未完成派工的人；每组按综合分从高到低排列。管理员始终手动选人，也可以选择忙碌人员。该状态根据已派工单计算，不代表排班或实时在岗。

每位人员显示未完成派工数、真实平均分和有效评分数。排序使用平滑分：

```text
综合分 = (3.5 × 5 + 有效评分总和) / (5 + 有效评分数)
```

无评分时，平均分显示“暂无评分”，评价数为 0，综合分用于排序时为 3.5。被完整撤下的评分不计入均分和综合分；只撤下文字不改变分数。管理员可打开人员详情查看完整评价。

## 举报、审核与恢复

评价提交后立即公开，由管理员事后审核。学生可举报公开评论；同一学生对同一评价最多保留一条待处理举报。管理员可驳回举报、仅撤下文字保留星级、撤下整条评分及文字，或封禁作者的评价功能；通过举报封禁作者时同时撤下被举报的文字，保留星级。管理员直接处理评价时也可选择只撤文字或撤下整条。所有处理都要求原因，并记录操作者和时间。

审核记录保留原始内容与评分供管理员核查，不向学生或维修模式公开。举报时保存当时公开的分数与文字快照；作者之后修改评价也不会改变举报证据，管理员举报列表展示该快照。误删后管理员可以恢复文字或整条评价；完整评分恢复后重新计入均分。未被封禁的学生在整条评价被撤下后，可以重新提交该工单评价。审核自己的评价或自己的举报由另一位管理员处理。

## 评价封禁

管理员可设置到期时间或永久封禁，也可提前解封；封禁和解封均须填写原因，记录操作者与时间，并通知学生。封禁只阻止新提交或修改星级及文字，不影响报修、阅读公开评价、查看既有评价和通知。已经发布的合规内容仍公开并计分；需要处理具体内容时另行审核。封禁到期后提交权自动恢复。

## 站内通知

学生端提供通知列表、未读数和标记已读。完工、评价撤下／恢复、举报受理及结果、封禁／解封都通过站内通知告知相关学生。仅撤下文字使用 `REVIEW_TEXT_REMOVED`，连评分一起撤下使用 `REVIEW_REMOVED`，避免误导学生认为分数仍计入或已被删除。举报处理通知只说明处理状态，不透露被举报学生的身份或处分细节；学生提交举报后的接口回执也不返回被举报评价作者、举报人身份或举报原因。此功能不发送业务邮件。

## API

以下接口均使用登录会话，并按 `X-Active-Role` 判断当前模式；多角色账号不能省略活动角色。错误状态遵循现有约定：未登录 `401`、角色或对象不可访问 `403`、无效参数 `400`、工单状态／评价状态冲突 `409`。

```text
GET  /api/reviews/technicians
GET  /api/reviews/technicians/{technicianId}
GET  /api/reviews/me/average
GET  /api/reviews/me/ban
GET  /api/reviews/tickets/{ticketId}/mine
PUT  /api/reviews/tickets/{ticketId}/mine       {"score": 1..5, "comment": "optional"}
POST /api/reviews/{reviewId}/reports             {"reason": "required"}

GET  /api/admin/reviews
GET  /api/admin/reviews/reports
GET  /api/admin/reviews/{reviewId}/audit
GET  /api/admin/reviews/students/{studentId}/ban
POST /api/admin/reviews/{reviewId}/moderation     {"action": "REMOVE_TEXT|REMOVE_ALL|RESTORE", "reason": "required"}
POST /api/admin/reviews/reports/{reportId}/resolve
                                                {"action": "DISMISS|REMOVE_TEXT|REMOVE_ALL|BAN_AUTHOR", "reason": "required"}
POST /api/admin/reviews/students/{studentId}/ban {"reason": "required", "expiresAt": "optional ISO local date-time"}
POST /api/admin/reviews/students/{studentId}/unban
                                                {"reason": "required"}
```

`GET /api/reviews/me/average` 只在维修模式下返回本人汇总，不提供逐条内容。公开列表与管理员审核页使用不同的数据视图，避免把评价作者或工单详情意外带到学生端。

`GET /api/reviews/me/ban` 向学生显示本人当前封禁状态，管理员的学生封禁接口用于审核；到期时间为空表示永久封禁。
有期限封禁的 `expiresAt` 接受浏览器 `datetime-local` 格式，例如 `2026-10-14T16:30`。

## 验证重点

集成测试应覆盖：未完工或非提交者拒绝评价；改派后只评最终完成人；禁止给自己评分；多角色接口隔离；分数、字数和一单一评约束；忙碌优先级与平滑排序；匿名公开视图；只删文字与删整条对均分的不同影响；恢复与重复提交；举报去重、处理和通知；限期／永久封禁及解封；管理员自审限制；已读通知隔离。
