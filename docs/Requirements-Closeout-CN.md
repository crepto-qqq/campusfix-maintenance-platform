# CampusFix 需求对照与收尾验收

本说明以团队需求文档中后半部分的 Requirements Analysis 为功能基准：五个模块、FR01–FR20。仓库早期文档中的 F11 优先级、F12 派单等是开发任务编号，与这套 FR 编号不是同一个编号体系。

## 工单沟通与通知

`GET /api/tickets/{ticketId}/comments` 返回按创建时间、ID 排序的留言。仅报修人、当前分配的维修人员、管理员可读取。返回作者姓名、发言时角色、正文和时间，不返回邮箱。

`POST /api/tickets/{ticketId}/comments` 接收 `{"body":"message"}`。正文不能为空且不得超过 2,000 字符。只有本人学生模式或当前维修人员模式可发布；COMPLETED、CLOSED、CANCELLED 工单只读。改派后旧维修人员立即失去读写权限。发布与通知处于同一事务，通知不包含留言正文；不给自己发留言通知。

首次派单分别生成报修人通知和维修人员通知。兼任两个角色的账号在各自工作台看到对应通知。留言通知只在接收方对应的工作角色中显示；旧维修人员的留言通知在改派后不再显示。原有改派通知仍保留，告知旧维修人员工作已转交。

## 分析指标

`GET /api/tickets/analytics` 仅管理员模式可访问。Dashboard 提供刷新按钮，切换到其他角色会清空并隐藏统计；统计接口失败不会阻止基础工单列表显示。

- 总量：包括所有状态的工单；等待派单：SUBMITTED。
- 已完成维修：COMPLETED 与历史 CLOSED 工单。
- 完成率：已完成维修数 ÷ 非 CANCELLED 工单数，无工单时显示 0%。
- 平均完成时间：从工单创建到历史中第一次转为 COMPLETED 的时长，单位为小时。只统计当前已完成／已关闭且有该历史的工单，页面显示样本数。缺少历史的旧工单不估算时间；没有样本时显示 No data yet。修改留言或证据不改变完工时长。
- 平均评分：全部未被撤下的有效星级，按每条评分计算；只撤文字仍计星级，撤下整条评分则不计。没有有效评分时显示 No ratings yet。
- 状态、类别、地点分布：统计全部工单；地点按保存的地点文本分组。
- 维修人员工作量：启用且具有维修角色的账号，显示其当前有效分配中 ASSIGNED、IN_PROGRESS、REOPENED 工单数，包含零工作量人员。不表示排班或实时在岗。

## 规则澄清

需求原文中的“维修开始前可编辑／取消”在当前实现中采用更严格的“派单前”，以免修改已进入调度流程的信息。最终提交需求文档时应采用这一明确规则。

维修人员完成实际维修后，在系统尚为 IN_PROGRESS 时上传说明与图片，再点击完成；上传证据本身不改变状态。当前允许不附证据直接完成，不应在演示中声称证据为强制项。

需求中的 Pending 对应当前 SUBMITTED；Emergency 对应调度优先级 CRITICAL。关闭与重新打开不是本次需求基准的必做流程，现有枚举保留历史兼容用途。

团队成员以 README 中的实际四人为准；原需求文档中的 Member 1–5 是过时的模块分配占位。个人贡献应由团队按实际提交和 Jira 记录填写，不由代码推断。

## 演示验收

1. 学生提交报修，附图片和地点。在 Conversation 留下进入房间的说明。
2. 管理员设优先级并派单。学生和维修人员在各自 Notifications 中看到派单通知。
3. 维修人员查看既有留言并回复。学生收到留言通知、可标记已读；其他学生不能打开该工单。
4. 管理员改派。旧维修人员不能再读取或发布工单留言；新维修人员能读到上下文并继续沟通。
5. 新维修人员开始任务、上传维修说明与照片、标记完成。学生收到状态和完工通知，留言变为只读。
6. 学生完成评分反馈。管理员看板显示完成数、评分和工作量变化，可刷新。
7. 用兼有多个角色的账号切换学生、维修、管理员工作台，确认通知及统计不跨角色显示。
8. 在手机宽度下检查看板与详情页，确认无横向溢出、按钮可用、长留言与地点能换行。

## 自动化与非功能验收

后端 `CloseoutIntegrationTest` 覆盖留言归属与角色、改派撤权、结束后只读、长度验证、自分配通知隔离、统计权限、空数据、完成时长、评分审核、工作量，以及并发完工只产生一次历史和通知。`CloseoutPersistenceTest` 使用临时文件数据库启动、关闭并重启服务，验证留言、派工、通知及统计保留。前端 `closeout.test.cjs` 覆盖输入验证、失败保留草稿、防重复提交、文本转义、角色切换时丢弃迟到的统计响应及统计失败状态。

完整命令见 README。测试使用内存数据库，不需要也不应删除真实数据库。已有 H2 文件由 Hibernate 新增留言表，不清空已有工单。

2026 年 10 月 19 日本地验证结果：后端 27 项测试、前端 36 项测试全部通过，JavaScript 语法检查与 `git diff --check` 通过。在独立内存实例中，通过浏览器验证了管理员只读留言、维修人员发送回复、开始与完成维修、结束后留言只读、学生接收派单／留言／完工通知、管理员统计及刷新。在 1280px 桌面宽度和 390px 手机宽度检查了页面；390px 下看板和详情页无横向溢出。该验证使用演示账号和数据，不代表真实邮件、地图及正式环境负载验收。

功能实现和自动化测试不等于所有非功能需求已经验收。真实 Brevo 邮件、有效 Google Maps key、不同浏览器与设备、预期并发下的响应时间、团队实际数据的升级及备份，应在目标环境中另行验证。尚未完成这些验证前，不应填写“全部非功能要求通过”。
