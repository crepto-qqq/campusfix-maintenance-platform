## 1. Overview

This branch implements the maintenance request (ticket) management features for the CampusFix system:

| Requirement | Description | Status |
|---|---|---|
| FR04 | Role-based access control (groundwork) | Implemented |
| FR05 | Submit maintenance request (title, description, category, location, urgency) | Implemented |
| FR06 | Upload issue images (one or more per request) | Implemented |
| FR07 | Edit or cancel a maintenance request before work begins | Implemented |
| FR08 | View maintenance request history for the current user | Implemented |

All features use the existing session-based authentication (HTTP session + `JSESSIONID` cookie). A user can only view and manage their own requests.

## 4. API Endpoints

Base URL: `http://localhost:8080/api`

### Tickets (FR05, FR07, FR08)

| Method | Path | Purpose |
|---|---|---|
| POST | `/tickets` | Create a maintenance request |
| GET | `/tickets` | List the current user's requests (newest first) |
| GET | `/tickets/{ticketId}` | Get a single request owned by the current user |
| PUT | `/tickets/{ticketId}` | Edit a request (only while `SUBMITTED`) |
| POST | `/tickets/{ticketId}/cancel` | Cancel a request (only while `SUBMITTED`) |

### Images (FR06)

| Method | Path | Purpose |
|---|---|---|
| POST | `/tickets/{ticketId}/images` | Upload one image (`multipart/form-data`, field name `image`) |
| GET | `/tickets/{ticketId}/images/{imageId}` | View an image |
| DELETE | `/tickets/{ticketId}/images/{imageId}` | Delete an image (only while `SUBMITTED`) |

### Role management (FR04)

| Method | Path | Purpose | Permission |
|---|---|---|---|
| PUT | `/users/{userId}/role` | Update a user's role | Administrator only |

## 5. Request / Response Formats

### Create / Edit request body

```json
{
  "title": "Air conditioner leaking",
  "description": "The unit on level 3 keeps dripping water.",
  "category": "HVAC",
  "location": "Library level 3",
  "urgency": "HIGH"
}
```

### Ticket response

```json
{
  "id": 1,
  "title": "Air conditioner leaking",
  "description": "The unit on level 3 keeps dripping water.",
  "category": "HVAC",
  "location": "Library level 3",
  "urgency": "HIGH",
  "status": "SUBMITTED",
  "createdAt": "2026-08-22T15:00:00",
  "updatedAt": "2026-08-22T15:00:00",
  "imageIds": [1, 2]
}
```

### Update role body (FR04)

```json
{
  "role": "MAINTENANCE_STAFF"
}
```

## 6. Business Rules

- A new request is created with status `SUBMITTED`.
- A user can only see and modify their own requests. Accessing another user's request returns `404` or `403`.
- Editing, cancelling, adding images, and deleting images are allowed **only while the status is `SUBMITTED`** (i.e. before maintenance work starts). Other states return `409 CONFLICT`.
- Image constraints:
  - Maximum 5 images per request.
  - Maximum 15 MB per image.
  - Only `image/*` content types are accepted.
- Role changes can only be performed by an `ADMINISTRATOR`; otherwise `403 FORBIDDEN`.

## 7. Test Steps

### 7.1 Setup

1. Start the backend:
   ```powershell
   cd backend
   .\gradlew.bat bootRun
   ```
   Wait until the log shows `Started BackendApplication` / `Tomcat started on port 8080`.
2. Open the frontend with **VS Code Live Server** (port 5500):
   - Right-click `frontend/index.html` → **Open with Live Server**.
   - The address bar must show `http://localhost:5500/index.html` (do **not** open via `file://`).
3. Stick to one hostname throughout testing (`http://localhost:5500`, not `127.0.0.1`).

Default administrator (auto-created on first run when the database is empty):

| Email | Password |
|---|---|
| admin@campusfix.edu | Value set locally through `CAMPUSFIX_ADMIN_PASSWORD` |

> If the database was created by an older version of the app, delete `backend/data` and restart so the `role` column is created fresh.

## 8. Known Issues / Notes

1. **Passwords are stored in plain text** (legacy behaviour carried over from the original `UserService`). FR02's "secure login" would ideally use a password hash such as BCrypt. This was intentionally left unchanged to avoid breaking existing accounts.
2. **CORS / hostname coupling**: the frontend builds the API base URL from the current page hostname (`http://${location.hostname}:8080/api`) so the session cookie is sent correctly. Always use `http://localhost:5500` (Live Server) and avoid mixing `localhost` and `127.0.0.1`.
3. **`file://` is not supported**: opening the frontend by double-clicking the HTML file breaks CORS and the session cookie. Use Live Server instead.
4. **Old database compatibility**: if the H2 database file was created before the `role` column existed, delete `backend/data` and restart the backend.
5. **No self-service staff/admin registration**: all self-registered accounts are `GENERAL_USER`. Staff and admin roles are assigned by an administrator via the role endpoint.
